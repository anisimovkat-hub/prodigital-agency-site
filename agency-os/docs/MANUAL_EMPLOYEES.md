## Миграция 0048

`profiles.id` становится независимым идентификатором карточки с UUID по умолчанию.
Для существующих зарегистрированных профилей `auth_user_id = id` сохраняет
внешний ключ к auth.users, уникальность и прежний контракт авторизации.
Ручная карточка: is_manual=true, auth_user_id=NULL, роль не owner.
Триггер отвергает ручную карточку с ID существующего пользователя Auth и
заполняет auth_user_id=id для штатной регистрации. Зарегистрированный профиль
без реального auth.users по-прежнему отвергается внешним ключом.
Политики RLS, is_admin, has_profile, задачи, связи проектов и signup-триггер
не меняются. Никаких фиктивных email, паролей, пользователей Auth или писем.

Подключение входа к существующей ручной карточке с сохранением истории пока
не реализовано: его нужно делать отдельным проверяемым действием, не создавая
второго сотрудника с тем же именем. Существующий код приглашения Виолетте не
передавался и не использовался.

Проверки: тесты серверного действия (owner-only, отсутствие Auth/invite side
effects, повтор имени, отказ без подтверждённой строки), TypeScript, ESLint,
production build. Живая миграция, ограничения Auth и RLS проверены в транзакции;
создание Виолетты подтверждено результатом SELECT и опубликованным UI.
Дополнительная отправка дубликата имени в production отклонена автоматической
проверкой разрешений как необязательная запись; дубль не создавался. Защита
от повторного имени проверена тестами действия и уникальным индексом БД.
