# Сотрудники для учёта задач без регистрации

Статус 26.10.2026: код подготовлен, 402 теста /53 файла, TypeScript, ESLint и
production build прошли. Форма проверена в локальном предпросмотре. Применение
миграции 0048 в production остановлено автоматической проверкой разрешений:
нужно отдельное согласие на изменение структуры сотрудников. Миграция не
применена, Виолетта ещё не создана, код не опубликован. Не объявлять этот этап
завершённым до согласия, проверки живой транзакции и реальной карточки.

Владелец добавляет сотрудника через `/employees` → «Добавить сотрудника».
Обязательное поле только имя; должность необязательна. Карточка участвует в
обычных выборах исполнителя, проектах и расчёте загрузки. Метка «Только учёт»
показывает, что сотрудник не получил вход в приложение.

`createEmployee` проверяет текущую сессию и роль owner, валидирует данные,
защищает от повторного имени и подтверждает вставленную строку. Роль новой
карточки — specialist; значения role/id/auth_user_id из формы не принимаются.
Auth API и invite_codes в этом действии не вызываются. Приглашение остаётся
отдельным необязательным действием с актуальным адресом production signup.

## Миграция 0048

`profiles.id` становится независимым идентификатором карточки с UUID по умолчанию.
Для существующих зарегистрированных профилей `auth_user_id = id` сохраняет
внешний ключ к auth.users, уникальность и прежний контракт авторизации.
Ручная карточка: is_manual=true, auth_user_id=NULL, роль не owner.
Триггер отвергает ручную карточку с ID существующего пользователя Auth и
заполняет auth_user_id=id для штатной регистрации. Зарегистрированный профиль
без реального auth.users по-прежнему отвергается внешним ключом.
Политики RLS, is_admin, has_profile, задачи, связи проектов и signup-триггер
не меняются. Никаких фиктивных email, паролей, пользователей Auth или писем.

Подключение входа к существующей ручной карточке с сохранением истории пока
не реализовано: его нужно делать отдельным проверяемым действием, не создавая
второго сотрудника с тем же именем. Существующий код приглашения Виолетте не
передавался и не использовался.

Проверки: тесты серверного действия (owner-only, отсутствие Auth/invite side
effects, повтор имени, отказ без подтверждённой строки), TypeScript, ESLint,
production build. Перед созданием Виолетты проверить живую миграцию и RLS
в транзакции, а после — наличие карточки и возможность выбора исполнителем.
