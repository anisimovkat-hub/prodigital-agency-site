## Следующий деплой

В `package.json`, `vercel.json` и `.github/workflows/ci.yml` нет применения SQL:
обычный Vercel deploy собирает приложение, сохраняет данные Supabase и не
повторяет миграции. В этом PR **не добавляется автоматический db push**.

Не запускать слепой `supabase db push`, `db reset` или все SQL файлы подряд на
production: CLI сравнивает версии, а старые timestamps и номера пока различаются.
Перед будущей автоматизацией миграций сначала нормализовать и проверить весь
baseline в отдельной задаче. Новые миграции применять только явно, после проверки
журнала; уже зарегистрированные 0049–0051 и KPI повторно не выполнять.

Создание ФЦК — отдельное согласованное изменение CRM, а не миграция схемы:
`scripts/create-fck-project.sql` идемпотентен и не входит в автоматический деплой.
