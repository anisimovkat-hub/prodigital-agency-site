# Telegram: согласование задач

Источник задач — CRM Agency OS. Интеграция не обращается к Notion и не зависит от
локального Python-бота: вебхук и ежедневная проверка работают на Vercel.

Каждый день в 09:00 по Москве сервис ищет активные задачи с дедлайном завтра,
создаёт черновик и присылает его владельцу в личный чат с ботом. В черновике
формат похож на обычное сообщение руководителя: жирный заголовок «проект //
задача», затем жирный короткий срок в виде `01.09 (ПН)` (а при упоминании
времени в названии — `01.09 (ПН) до 12:00`) и полный текст из описания задачи.
Между каждым блоком остаётся пустая строка. Направление остаётся в CRM для
планирования и не выводится отдельной служебной строкой. В описании можно
выделить важное через `**двойные звёздочки**`, добавить ссылку как
`[название](https://...)`, абзацы, списки и эмодзи. До нажатия кнопки
«Отправить сотруднику» сообщение в рабочий
чат не уходит. «Внести
правки» переводит черновик в режим редактирования: следующим сообщением в
личный чат нужно прислать полный новый текст.

Описание стоит писать короткими смысловыми блоками: «Нужно подготовить…»,
«Нужно сделать…», «Подготовить…». Формулировки нейтральные, без обращения на
«ты» или «вы»; при необходимости в отдельном абзаце можно добавить причину,
контекст или ссылку на пример.

Для повторяющихся задач база создаёт экземпляры сразу на сегодня и завтра,
поэтому завтрашнее напоминание тоже можно проверить за сутки.

## Первое включение

В Vercel должны быть заданы **Sensitive** переменные окружения:

- `TELEGRAM_BOT_TOKEN` — токен от BotFather;
- `TELEGRAM_WEBHOOK_SECRET` — случайный секрет для заголовка вебхука;
- `TELEGRAM_SETUP_CODE` — одноразовый код подключения владельца;
- уже существующие `CRON_SECRET`, `NEXT_PUBLIC_SUPABASE_URL` и серверный ключ
  Supabase.

После установки вебхука владелец один раз пишет боту в личный чат
`/start <TELEGRAM_SETUP_CODE>`. Бот сохраняет только ID этого личного чата и
сразу показывает все новые задачи на завтра. Команда `/pending` повторно
проверяет такие задачи вручную и обновляет ещё не отправленные черновики.

При добавлении бота в рабочую группу он сохраняет группу и, если в названии
группы есть ровно одно имя активного сотрудника CRM, автоматически привязывает
её к этому сотруднику. Неоднозначные группы остаются непривязанными и не могут
получить задачу — это намеренная защита от отправки не тому человеку.
