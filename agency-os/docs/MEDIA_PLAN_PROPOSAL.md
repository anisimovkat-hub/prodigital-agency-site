# Плановые KPI и медиапланы — предложение модели

Статус: предложение для согласования перед миграцией и UI. Дата: 2026-08-13.

## Рекомендация

Источник истины для плана — Agency OS, а Google Sheets остаётся удобным входным форматом.
Пользователь может создать план вручную или импортировать стандартизированный лист; после
импорта система хранит нормализованный снимок и больше не зависит от того, как владелец позже
переставит колонки в исходной таблице.

## Модель данных

### `media_plans` — шапка плана

- `id uuid`
- `project_id uuid` — обязательный проект
- `workstream text null` — направление внутри проекта до появления отдельного справочника
- `period_start date`, `period_end date`
- `name text` — например «Август 2026 · Telegram Ads»
- `status draft | approved | archived`
- `currency text` — ISO 4217 (`RUB`, `EUR`, `GBP` и т. п.)
- `source_type manual | google_sheets`
- `source_spreadsheet_id text null`, `source_range text null`
- `source_url text null`, `imported_at timestamptz null`
- `created_by`, `created_at`, `updated_at`

Ограничения: период корректный; валюта обязательна; одновременно один `approved`-план на
проект + направление + период + валюту. План другой валюты хранится отдельной строкой.

### `media_plan_metrics` — строки целей

- `id uuid`, `media_plan_id uuid`
- `metric_key text` — стабильный ключ: `spend`, `impressions`, `clicks`, `reach`,
  `conversion:<action_type>`, `revenue`
- `label text` — понятная подпись владельцу/клиенту
- `target_value numeric`
- `unit money | count | percent`
- `conversion_action_type text null` — точное соответствие `ad_conversions.action_type`
- `campaign_id uuid null` — необязательная привязка к одной кампании
- `sort_order integer`, `notes text null`

Производные KPI (CTR, CPC, CPA) не вводятся отдельными независимыми целями: они считаются
из базовых плановых значений. Это предотвращает противоречие «план кликов один, план CTR —
другой». Если нужна самостоятельная бизнес-цель по CPA, её можно добавить после пилота.

## План/факт

Факт читается только из существующих `ad_campaign_metrics` и `ad_conversions`. Для каждого
плана система применяет его период, проект, опциональные направление/кампанию и точный
`conversion_action_type`. Результат выдаётся строками:

`метрика · план · факт · выполнение % · отклонение`.

Деньги агрегируются только внутри валюты плана. Если кабинет содержит другую валюту, UI
показывает отдельный блок и не считает общий процент. Автоматической конвертации в рубли в
этом этапе нет.

## Импорт Google Sheets

Первая версия использует фиксированный лист `Agency OS` с колонками:

`metric_key | label | target_value | unit | conversion_action_type | campaign_external_id | notes`

Готовый пример строк находится в `docs/MEDIA_PLAN_IMPORT_TEMPLATE.csv`. Его можно импортировать
в новый Google Sheet и заменить целевые значения, не меняя заголовки колонок.

В форме пользователь вставляет ссылку, выбирает проект, период, валюту и диапазон. Сервер
извлекает `spreadsheetId`, читает только указанный диапазон через Google Sheets API
`spreadsheets.values.batchGet`, валидирует все строки и показывает предпросмотр. Запись в БД
происходит только после подтверждения. Повторный импорт создаёт новую версию черновика, а не
тихо переписывает утверждённый план.

Sheets API умеет получать несколько диапазонов одним запросом и возвращает значения строками;
для чтения достаточно scope `spreadsheets.readonly`. Использование `values.get/batchGet`
легче и быстрее полного `spreadsheets.get`, потому что форматирование листа нам не нужно.

## Доступ и UI

- Создание, импорт и утверждение: owner/admin.
- Чтение: участники доступного проекта по существующей `can_access_project`; публичный отчёт
  получает только агрегированный план/факт через отдельную SECURITY DEFINER RPC.
- В проекте: блок «Плановые KPI» с кнопками «Новый план» и «Импорт из Google Sheets».
- В аналитике: компактная карточка «План/факт» над детализацией рекламы.
- В клиентском отчёте: только утверждённый план, без исходной ссылки и внутренних заметок.

## Порядок реализации после согласования

1. Миграция таблиц, индексов, RLS и manual `types.ts`.
2. Чистая библиотека расчёта план/факт с unit-тестами и строгим разделением валют.
3. Ручная форма создания/редактирования плана.
4. Предпросмотр и импорт стандартного листа Google Sheets.
5. Карточка в `/analytics` и безопасный агрегат в клиентском отчёте.

## Решение, требующее согласования

Рекомендуемый MVP: **один утверждённый план на проект/направление/период/валюту**, а
кампании — необязательная детализация строк. Альтернатива — отдельный медиаплан на каждую
кампанию — усложнит создание, затруднит проекты с часто меняющимися кампаниями и поэтому не
рекомендуется для первой версии.
