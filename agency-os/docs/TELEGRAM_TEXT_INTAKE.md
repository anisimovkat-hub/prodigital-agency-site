# Джарвис: текст → задача в CRM → согласование → рабочий чат

27.10.2026. Код подготовлен, рабочий бот ещё не обновлён. Миграции 0049–0051
применены с согласия владельца; проверки базы выполнены в транзакции с откатом.
PR в `claude/redesign-stage1-20261027`, Vercel Preview и выпуск — после отдельного «да».

## Поведение

- Владелец пишет @ai_Pro_Digital_bot текст, в том числе продиктованный Wispr Flow.
  Проверяются секрет вебхука, личный чат и `from.id` по owner_chat_id.
- Проект/сотрудник определяются по имени и утверждённым aliases. Регистр и ё/е
  игнорируются. Опечатки на 1–2 буквы дают только предложения, которые выбирает владелец.
  Имя клиента не выбирает проект автоматически: у БЛЭК/Манифеста есть несколько проектов.
- Если нет проекта, исполнителя или срока — вопрос с кнопками. «Другой» позволяет
  ввести название; сотрудники предлагаются по команде/ответственным проекта.
  Отсутствие срока требует ответа; «Без срока» сохраняет due_date=NULL.
- Сроки: сегодня/завтра/послезавтра, дни недели, до 15-го, 15.11, через 3 дня.
  Календарь Europe/Moscow; невалидные и противоречивые даты требуют уточнения.
- Несколько задач: строки или «и ещё», максимум 20. Заголовок — первая фраза
  без распознанных служебных полей, описание — остальное, ссылки сохраняются.
- На согласование используется общий `sendTelegramTaskPreview` из утреннего сценария.
  CRM-задача имеет creator_id владельца и status=todo; `owner_approval_pending=true`
  закрывает её от сотрудников через RLS. Доставка — pending_approval в отдельной таблице.
- «Внести правки»: можно прислать новый текст или «срок завтра», «исполнитель Софа»,
  «название: …», «описание: …». Обновляются поля tasks, затем общий черновик.
- «Отменить» отменяет новую задачу. Через 24 часа от создания она также отменяется;
  cron БД проверяет раз в минуту, а при нажатии кнопки срок проверяется сразу.
  Прежние утренние напоминания отменяют только сообщение, не исходную задачу сотрудника.
- При отправке выполняется атомарный захват; нажатие старой кнопки не отправляет дубль.
  После подтверждения Telegram флаг приватности снимается. Неопределённый сетевой
  результат остаётся sending до ручной проверки рабочего чата, без автоматической повторной отправки.
- Голосовые: только очередь file_id/file_unique_id и ответ
  «Пришлите текстом через Wispr — голосовые подключим на сервере».
  Скачивания, расшифровки, OpenAI/Anthropic API и других платных моделей нет.

## Данные и доступ

0049: aliases проектов/профилей, приватность новых задач, состояния уточнений,
очередь голосовых, отмена и истечение срока. 0050: глобальные квитанции сообщений,
чтобы повтор ответа на уточнение не создавал новую задачу после завершения диалога.
0051: единый порядок блокировок отправки/отмены и отмена задач при сбое отправки
самого владельческого черновика. RPC мутаций доступны только service_role;
пользовательские сессии подчиняются RLS. Секреты остаются в прежних переменных Vercel.

Синонимы не заполнены: нужен ответ по таблице согласования. Изменение вариантов
в интерфейсе — в карточке проекта и карточке сотрудника, только владельцем.
Новые схемы не создают и не активируют проекты. Мос.ру завершён.
ФЦК («Производительность РФ», «производительность.рф») отсутствует в CRM:
внести только в список решений, без создания до отдельного поручения.

## Проверки и выпуск

- Unit: две точные фразы владельца и 18 дополнительных фраз на основе реальных
  названий CRM; дополнительные проверки календаря, опечаток, частичных правок,
  авторизации вебхука и редактирования синонимов.
- `scripts/check-telegram-task-intake.sql`: создание без дубля, creator,
  квитанции уточнений, недоступность сотруднику/доступ владельцу, права RPC,
  отмена, истечение срока, однократный захват отправки. Все данные откатываются.
- Перед PR: TypeScript, ESLint, весь Vitest и production Webpack build.
- После разрешения: PR в рабочую ветку, проверка Vercel Preview. Живой тест
  владелец проводит тремя задачами; сотрудникам отправлять только её кнопкой.
- Preview не должен перерегистрировать webhook или запускать production cron.
  У бота один webhook: живой тест production выполняется только после разрешённого выпуска.
