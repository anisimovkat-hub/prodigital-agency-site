## Короткий статус

Production-MVP работает на `https://prodigital-os.vercel.app` из ветки
`claude/agency-ops-mvp-design-ykrrn0`, Root Directory — `agency-os/`. Прикладные миграции
применены до `0036`. Работают проекты, клиенты, сотрудники и RLS, задачи/канбан/повторы,
два Google Calendar без дублей и приёмов пищи, учёт времени задач, медиапланы,
единая аналитика Meta + Instagram и публичные клиентские отчёты.

Основная Meta-статистика загружается ежедневно Vercel Cron. Главный дашборд не показывает
падение показов и техническую несвежесть; тревога CPA возникает только при одновременном
снижении количества заявок. Самостоятельное восстановление пароля работает через Supabase Auth.
Период отчёта и ручной загрузки Meta выбирается одной кнопкой-календарём в шапке `/analytics`.
Выпадающее окно содержит готовые интервалы, два месяца календаря и «Обновить»; отдельные
поля дат и селекторы периода удалены. Оно закрывается кликом вне окна или Escape; будущие
даты недоступны. Ручная догрузка Meta спрятана в «Обновить данные Meta» и видна только при
связанном кабинете; технический блок Яндекс.Директа из отчёта убран. Загрузка получает
статистику только на чтение.

Стартовый экран `/analytics` больше не выводит сводные показатели по всем проектам. По
умолчанию он показывает последние 7 дней отдельными компактными карточками активных проектов:
главную цену лида/цели, расход и результаты. Сверху доступны период, переход к проекту и
поиск; сравнение берёт предыдущий интервал той же длины. Денежные значения и цена цели
появляются только при одной валюте и сопоставимой цели; иначе карточка прямо сообщает об
ограничении. `0035_project_color.sql` добавила настраиваемый цвет проекта в production.
Подробная аналитика открывается после выбора проекта.

Y1 Яндекс.Директа реализован и опубликован в коммите `8aa6a23`: `YANDEX_DIRECT_TOKEN` хранится
как sensitive Production/Preview env, а owner-only `/analytics` запускает read-only

## Правила безопасности и качества

- Meta/Яндекс/ИИ-токены — только sensitive env Vercel, никогда в Git, Supabase или логах.
- Интеграции рекламы — read-only. Не менять кампании, ставки и бюджеты.
- RLS не ослаблять; `src/lib/supabase/types.ts` обновлять вручную при каждой миграции.
- Не суммировать разные валюты; цель конверсии всегда указывать явно.
- Графики — лёгкий SVG, не добавлять `recharts`.
- Перед каждым push: `tsc --noEmit`, ESLint, Vitest и production build.
- Коммитить только собственные файлы; не использовать `git add -A` в общем репозитории.
- После изменения поведения обновлять `CLAUDE.md`, `PROJECT_STATUS.md`, `PROJECT_MEMORY.md`,
  `DECISIONS.md` и профильный документ аналитики.
