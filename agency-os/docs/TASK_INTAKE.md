# Постановка задач: из чата → в CRM + текст для пересылки

Единый рабочий процесс для Claude и Codex. Владелец (Катерина) диктует/пишет задачу
свободным текстом (голосовая расшифровка, заметка, саммари созвона), а ассистент:

1. **Создаёт задачу в CRM** (таблица `tasks` в Supabase, проект `ihsjgzzdihjesblkuylz`).
2. **Выдаёт готовый текст** в шаблоне владельца — для пересылки сотруднику в его ТГ-чат.

Сотрудников в CRM для этого добавлять не нужно: задача оседает у владельца на доске/в
проекте, а исполнитель получает работу текстом в чат.

## Шаблон текста для пересылки (обязательный формат)

```
<Проект> // <Краткое название задачи> // до <ДД.ММ>

<Краткое описание — что сделать и зачем>

<Ссылки на документы — если есть>

<Подзадачи по пунктам, пояснения — если нужно>
```

Стиль (по примерам владельца): первая строка — жирным; разделы с жирными подзаголовками
(Посадочная, Медиаплан, Гео, Аудитория, Бюджет…); подзадачи — списком; советы/нюансы —
курсивом; ссылки — прямо в тексте; язык русский, кратко, в повелительном наклонении.

## Как создавать задачу в CRM

Поля `tasks`:
- `title` — краткое название (та же формулировка, что во второй части шапки).
- `project_id` — по названию проекта (fuzzy). Если проект не найден/неоднозначен — **спросить**,
  не угадывать. Список проектов см. в таблице `projects`.
- `assignee_id` — по имени сотрудника (профили: Катерина=owner; Инна, Илона, Екатерина,
  Софа, Алёна=specialist). Если исполнитель не назван — оставить пустым или спросить.
- `creator_id` — профиль владельца (Катерина).
- `due_date` — распарсить дедлайн («до 15-16.07», «завтра к обеду», «23-24.07» → выбрать
  конкретную дату; при диапазоне брать крайнюю). Если срока нет — оставить пустым.
- `priority` — `low`/`medium`/`high`/`urgent`. По умолчанию `medium`; «срочно/критично/сегодня»
  → `high`/`urgent`.
- `task_type` — из enum: `ads`/`creative`/`analytics`/`website`/`content`/`report`/
  `communication`/`other`. Подобрать по смыслу; по умолчанию `other`.
- `workstream` — направление/кампания внутри проекта (свободная метка), если уместно.
- `description` — краткое описание + пояснения + ссылки.
- `status` — `todo`.
- Подзадачи-пункты → строки `task_checklist_items` (`task_id`, `title`, `position`), либо
  отдельные подзадачи через `parent_task_id`, если это самостоятельные задачи с исполнителями.

После вставки — подтвердить созданную строку (`.select(...).maybeSingle()`), вернуть её id.

## Порядок ответа ассистента

1. Если чего-то критичного не хватает (проект / дедлайн / исполнитель неоднозначны) —
   задать **один** уточняющий вопрос, не выдумывать.
2. Создать задачу в CRM.
3. Выдать блок текста в шаблоне выше — готовый к копипасту в ТГ-чат сотрудника.
4. Одной строкой сообщить, что задача заведена (проект, исполнитель, дедлайн).

## Примечания

- Несколько задач в одном сообщении — создавать по одной, для каждой свой блок текста.
- Ссылки владельца (Google Docs/Sheets/сайты) переносить как есть.
- Не путать: задача в CRM — для учёта у владельца; текст — для исполнителя в чат.
