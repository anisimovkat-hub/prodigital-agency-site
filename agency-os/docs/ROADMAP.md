# Дорожная карта Agency OS

Обновлено: 2026-08-09

Карта развития под формат работы владельца (Катерина): личный планировщик дня,
видимость перегруза и делегирования, оцифровка часов → прибыльность проектов и,
как большой отдельный блок, — сквозная аналитика рекламы по API.

Принцип: брать один рабочий инкремент, проверять на production и только затем переходить
к следующему. Ядро этапов 0–2 уже работает; активная разработка сейчас сосредоточена на
рекламной аналитике Meta.

## Этап 0 — Единый «командный центр» (СДЕЛАНО)

**Цель:** один экран, где сразу видно и день, и всё, что требует внимания.

- **Лента дня**: события личного календаря (со временем) + задачи владельца на сегодня,
  с чётким разделением «Сегодня» и «Просрочено» (не сваливать в кучу).
- **Панель «Требует внимания»**: агрегирует сигналы в один блок —
  мои просроченные, делегированные просроченные, задачи без исполнителя,
  проекты в красной зоне (health=red), активные проекты без единой открытой задачи
  («замолчали»). Каждый сигнал кликабелен и ведёт в нужный список.

Блоки работают на production; дальнейшие изменения здесь — отдельные UX-улучшения.

**UX-инкремент 2026-08-13:** задачи владельца подняты в верхнюю рабочую зону дашборда,
получили чекбоксы завершения и встроенную просрочку; Google Calendar занимает компактную
правую колонку, а отдельный широкий блок делегированной просрочки устранён.

**Meta-инкремент 2026-08-13:** портфель проектов использует скользящие семь дней реальных
данных Meta. Расход и стоимость результата разделяются по валюте, разные цели не сворачиваются
в ложный общий CPA, а ручной KPI больше не подменяет оперативную рекламную статистику.

## Этап 1 — Повторяющиеся отчёты и аудиты (ЯДРО СДЕЛАНО, РАСШИРЕНИЕ ПОЗЖЕ)

- **Контент**: владелец даёт список «проект → дни недели → исполнитель», заводим шаблоны
  в `recurring_tasks`. Работает на уже применённой 0006.
- **Доработка шаблона**: добавить в `recurring_tasks` `description` и шаблон чек-листа
  (напр. `checklist_template text[]`) + ссылки; `generate_recurring_tasks()` копирует их
  в созданную задачу и заполняет `task_checklist_items`. Тогда «Аудит рекламных кампаний»
  появляется уже с готовым чек-листом и ссылками на отчёты.
- **Опционально**: частота «ежемесячно / по числу месяца» для месячных отчётов.

## Этап 2 — Учёт времени → прибыльность проектов (СДЕЛАНО)

- `time_entries` хранит ручной проектный таймер, `task_time_entries` — автоматические интервалы
  статуса «В работе». Параллельные интервалы одного сотрудника делятся между задачами.
- Финансовые поля проекта, отчёт неделя/месяц, часы на проект и ₽/час работают на production.

## Этап 3 — Аналитика рекламы по API (В РАБОТЕ, текущий приоритет)

Meta уже подключена и хранит реальные данные на всех уровнях. Ближайший порядок:

1. Автоматическая ежедневная загрузка через Vercel Cron; сейчас sync запускается кнопкой.
2. Панель «Требует внимания» с period-over-period аномалиями.
3. Предупреждения: рост CPL/CPA, падение показов, расход без конверсий.
4. Пересчёт USD/EUR/IDR и других валют в рубли без смешения исходных валют.
5. UI ручной привязки отдельной кампании к проекту.

Яндекс.Директ и ИИ-рекомендации отложены владельцем. Архитектурные правила:

- **Прямой API, НЕ Google Sheets/Adveronix.** Причина: в Sheets не затащить конверсии по
  многим целям, а нужны промежуточные цели, звонки, заявки. Своя схема хранит любое число целей.
- **Модель данных**: `ad_accounts` (project_id, platform, external_account_id, credentials_ref) —
  несколько кабинетов на проект; `ad_metrics` (ad_account_id, date, spend, impressions, clicks…);
  `ad_conversions` (ad_account_id, date, goal_name, count) — много целей на кабинет.
- **Синхронизация**: НЕ pg_cron (не умеет внешние HTTPS-вызовы), а ежедневная serverless-функция
  (Vercel Cron / Supabase Edge Function) с upsert.
- **Следующая площадка позже — Яндекс.Директ**: один OAuth-токен управляющего аккаунта,
  адаптер пишет в ту же модель данных.
- **Алерты**: таблица правил-порогов → ежедневная проверка подсвечивает «критично»
  (рост CPL, ноль конверсий, слив бюджета).
- **Ёмкость**: хранилище НЕ проблема (дневные агрегаты — единицы МБ/год при лимите 500 МБ).
  Реальные ограничения: (1) на free база засыпает и нет бэкапов → для ежедневной автозагрузки
  перейти на **Supabase Pro (~$25/мес)**; (2) каждая площадка — своя интеграция (OAuth, токены,
  лимиты); (3) поддержка. Поэтому — по одной площадке за раз.

## Этап 4 — ИИ-анализ рекламы (ОТЛОЖЕНО)

- Сравнение периодов, подсветка аномалий, базовые подсказки по оптимизации.
- Работает **только поверх данных Этапа 3**. Использует платный Claude API (ранее отклонён по
  цене) — включать «по кнопке», не постоянно, чтобы контролировать расходы.

## Инфраструктурные развилки

- **Supabase Pro (~$25/мес)** — становится нужен на Этапе 3 (надёжная ежедневная синхронизация,
  отсутствие засыпания БД, бэкапы). До этого free-тарифа хватает.
- **Vercel Hobby** формально некоммерческий; при росте — Pro.
- Хранилище для всех этапов 0–3 умещается в 500 МБ free-тарифа с большим запасом.
