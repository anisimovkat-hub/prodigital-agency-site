## Быстрый откат без новой сборки

Откат подготовлен как переключение на уже готовый production `590e2b2`.
Схему Supabase не откатывать: добавленные поля/RPC совместимы с прежним приложением.

1. При откате отменить только ещё не отправленные новые intake-задачи:
   `scripts/rollback-jarvis-pending-intake.sql`. Строки сохраняются, старые задачи
   и их утренние черновики не меняются. Lock timeout 2 с, statement timeout 10 с.
   Состояние `sending` не отменяется: дождаться завершения конкретного запроса,
   проверить рабочий чат; автоматически повторно не отправлять.
2. [Vercel agency-os](https://vercel.com/katerina-anisimova/agency-os) →
   **Instant Rollback** → проверить target `590e2b2`, deployment `3VgAWRTu…` →
   **Continue** → **Confirm Rollback**. Не выбирать Preview/новую сборку и не
   нажимать Redeploy. В штатном случае это несколько действий за примерно минуту.
3. Проверить production domain и webhook/cron logs. Доступ к данным и расписание
   прежнего production восстанавливаются вместе с выбранной сборкой. Приватные
   новые отменённые intake-задачи сохраняются для разбора, голоса в очереди не удаляются.
4. После Instant Rollback Vercel отключает автоматическое назначение production
   domains новым push. Новый выпуск требует явного Undo Rollback/Promote после проверки.

До выпуска интерфейс Instant Rollback проверен без подтверждения: на Hobby
он доступен. После выпуска обязательно убедиться, что previous — именно `590e2b2`.
Источник механизма: https://vercel.com/docs/instant-rollback
