# Еженедельные статусы рекламы в Telegram

Каждый активный сценарий из `telegram_weekly_status_scenarios` запускается Vercel
cron в своём UTC-слоте: сейчас есть понедельник 08:00 `Europe/Moscow`
(`0 5 * * 1` UTC) и 10:00 (`0 7 * * 1` UTC). Поле `schedule` должно совпадать
с одним из этих слотов; для иного времени нужен новый cron-триггер. Он берёт только
предыдущую полную неделю — с понедельника по воскресенье — и формирует один пост
на проект. Бот не обращается к рекламному кабинету: источником служат
нормализованные строки Agency OS.

## Где настраивать новый статус

1. В `telegram_weekly_status_scenarios` добавить проект, канал, получателя
   (`recipient_profile_id` для сотрудника с единственным привязанным рабочим
   чатом или точный `recipient_chat_id`), расписание, ссылку на отчёт, шаблон
   `project_weekly_ad_status` и флаг активности.
2. В `telegram_weekly_status_directions` добавить направления сценария: название,
   канал и один проверенный счётчик Метрики. Если у проекта несколько рекламных
   кабинетов, обязательно задать `ad_account_id`. Кампании без `CounterIds` попадут
   в отчёт только при явном `include_counterless_campaigns = true`; сначала
   проверить, что весь этот кабинет относится к тому же направлению и счётчику.
   Направление можно связать с `project_ad_directions`: тогда статус ограничивается
   его явно назначенными кампаниями. Для Kolvika эта связь обязательна.
3. В `telegram_weekly_status_goals` добавить GoalID, бизнес-ярлык, вид цели и,
   при необходимости, подпись ценности. Для AI-лендингов отметить три обращения
   `include_in_contact_cpa = true`.

Цели одинакового смысла из разных счётчиков остаются разными строками. Результаты
агрегируются только внутри ключа `project_id + direction_id + counter_id + goal_id + date`.

## Данные и защита от ложных цифр

- Расход попадает в статус только из строк `spend_includes_vat = true`.
- Цель с отсутствующим или неполным измерением выводится как `нет данных`, а причина
  сохраняется в `telegram_weekly_status_deliveries.last_error` и журнале cron.
  При любой такой ошибке публикация блокируется (`status = blocked`), а не
  отправляется частичный пост. Для привязанного кабинета дополнительно проверяются
  успешная загрузка после конца отчётной недели и покрытие каждой строки
  кампании/дня по каждой выбранной цели.
- CPA не считается при нуле конверсий: цель получает `0 / —`.
- Ценность цели выводится только из её собственного `Revenue_<goal_id>_LC`. Для
  покупки без покупок показывается `0 ₽`; отсутствующая ценность — `—`.
- `display_title`, `show_direction_heading` и `spend_label` в сценарии позволяют
  настроить короткий статус одного направления без клиентских условий в коде.
- Резервный лист можно описать в `fallback_source` сценария и `fallback_match`
  направления, но он не заменяет нормализацию и не может смешивать разные счётчики.

## Kolvika

Сценарий Kolvika отправляется только в личный чат владельца, сохранённый ботом
как `telegram_bot_settings.owner_chat_id`, по понедельникам в 08:00 МСК.
В чат Софы бот этот статус не отправляет: владелец пересылает проверенный пост
самостоятельно. Идемпотентный скрипт `scripts/configure-kolvika-weekly-status.sql`
создаёт сценарий **неактивным**, проверяет явные назначения кампаний и берёт
точный ID уже привязанного личного чата. Активировать его можно лишь после
применения миграции 0046 и проверки полной недели и цифр. Направления:
`14496817` (Gems4U), `71291494` (Kolvika Center), `112938684` (AI-лендинги).

| Направление | Цели в конфигурации |
| --- | --- |
| Gems4U | Корзина `194376727`, Покупка `3014496817`, Клик по номеру `347388444`, Мессенджеры `157962814` |
| Kolvika Center | Корзина `224072509`, Клик по номеру `158184796` |
| Kolvika Jewelry — AI-лендинги | Отправка формы `661982976`, Клик по номеру `661983554`, Мессенджеры `661983342` |

Для корзины нужно задать `value_label = "Стоимость товаров в корзинах"`, для покупки —
`"Выручка по покупкам"`. У целей AI-лендингов нужно поставить
`include_in_contact_cpa = true`. Покупка и мессенджеры Kolvika Center не
добавляются до появления подтверждённых GoalID. Новые цели, направления и
получатели меняются в конфигурационных таблицах, а не в шаблоне бота.

## ИНОМ

Отдельный сценарий для проекта `Ином // СНТ`, кабинета `fortilda26` и счётчика
`109204270`. Для него нужен один блок без повторного заголовка направления:
`display_title = 'Отчёт ИНОМ (запасной аккаунт fortilda26)'`,
`show_direction_heading = false`, `spend_label = 'Расход'`. Две **разные** цели:

| Строка статуса | GoalID | Вид |
| --- | --- | --- |
| Страница «Спасибо» | `559741388` | form |
| CRM: Заказ создан | `559241229` | form |

Обе цели считаются отдельно: количество и CPA = расход с НДС / количество
достижений соответствующей цели. Не складывать их в «Заявки»: за 28.09–04.10
Agency OS показывает 9 достижений страницы «Спасибо» и 1 CRM-заказ, тогда как
в ручном примере было указано 10 заявок. Кампании без номера счётчика допустимо
включать только после проверки привязки всего кабинета `fortilda26` к ИНОМ.
Данные кабинета успешно обновлены 19.10.2026; за неделю 12–18 октября в Agency OS
видны 14 достижений «Спасибо» и 3 CRM-заказа. До проверки привязки рабочего
Telegram-чата Софы и применения миграции 0046 сценарий оставлять неактивным.
Подготовленный конфигурационный скрипт — `scripts/configure-inom-weekly-status.sql`;
он идемпотентен и при первом запуске создаёт **неактивный** сценарий.
