# Еженедельные статусы рекламы в Telegram

## VK и Telegram Ads: черновики владельцу

Миграция `0047_weekly_status_multichannel_review.sql` расширяет прежнюю модель:
неяндексовое направление выбирает один кабинет и конкретные кампании либо
проверенный префикс их названий. Счётчик Метрики ему не нужен. Цели и подписи
задаются в конфигурации; VK и Telegram Ads не смешиваются даже внутри одного
проекта. Для охватной кампании можно явно указать `allow_no_goals = true`.

Расход без подтверждённого НДС допускается только с отдельной подписью
`spend_label` и `require_vat = false`: бот не называет его расходом с НДС.
Сценарии по умолчанию имеют `delivery_mode = owner_review` и отправляются в
личный чат владельца из `telegram_bot_settings.owner_chat_id`, даже если позже
для сценария будет задан чат сотрудника. Переход к `staff_auto` — отдельное
действие после одобрения формата; оно использует точно указанный чат или профиль.
Неполные данные в режиме `owner_review` видны как `нет данных` с заметным
предупреждением. В `staff_auto` та же неполнота блокирует отправку целиком.

`scripts/configure-prin-soda-weekly-status.sql` готовит **неактивные** сценарии
«ПРИН» и «СОДА» в одном CRM-проекте. Он требует подключённые напрямую VK и
Telegram Ads кабинеты, проверяет префиксы кампаний и не берёт старый импорт из
Google-таблицы, чтобы не удвоить расход. Владелец сначала сверяет полную неделю
с исходной таблицей. Лишь после применения миграций 0045–0047, проверки
актуальности импорта, цифр и чата можно поставить `is_active = true`.
`coverage_rules` отмечает общие префиксы каждого бизнеса в общем кабинете:
новая кампания с расходом, которую не покрывает ни одно направление статуса,
вызывает предупреждение владельцу и блокирует `staff_auto`.
В Telegram Ads отдельно сохраняются `joins` и `actions`; отсутствующее поле
`actions` остаётся неизвестным, а не нулём. В первоначальном сценарии показаны
только проверенные вступления. Для новых направлений и проектов меняются
конфигурационные строки, не шаблон сообщения.
Для VK отсутствие `base.goals` тоже остаётся неизвестным; только явное значение
`0` считается измеренным нулём. Явные нулевые дни обеих площадок сохраняются.
После staging владелец может запросить черновик за предыдущую полную неделю
командой `/status Прин` или `/status Сода` в личном чате с ботом. Команда не
включает расписание и не отправляет сообщение сотруднику; `/status` без имени
показывает доступные сценарии.

Каждый активный сценарий из `telegram_weekly_status_scenarios` запускается Vercel
cron в своём UTC-слоте: сейчас есть понедельник 08:00 `Europe/Moscow`
(`0 5 * * 1` UTC) и 10:00 (`0 7 * * 1` UTC). Поле `schedule` должно совпадать
с одним из этих слотов; для иного времени нужен новый cron-триггер. Он берёт только
предыдущую полную неделю — с понедельника по воскресенье — и формирует один пост
на проект. Перед отправкой Agency OS обновляет за эту неделю только цели,
указанные в сценарии, через свой общий импорт рекламных кабинетов и сохраняет
результат в нормализованных таблицах. Бот читает именно эти таблицы; отдельного
кода для получения статистики площадок в боте нет.

## Где настраивать новый статус

1. В `telegram_weekly_status_scenarios` добавить проект, канал, получателя
   (`recipient_profile_id` для сотрудника с единственным привязанным рабочим
   чатом или точный `recipient_chat_id`), расписание, ссылку на отчёт, шаблон
   `project_weekly_ad_status` и флаг активности.
2. В `telegram_weekly_status_directions` добавить направления сценария: название,
   канал и один проверенный счётчик Метрики. Если у проекта несколько рекламных
   кабинетов, обязательно задать `ad_account_id`. Кампании без `CounterIds` попадут
   в отчёт только при явном `include_counterless_campaigns = true` и списке
   назначенных кампаний. Принадлежность каждой кампании нужно проверить.
   Направление можно связать с `project_ad_directions`: тогда статус ограничивается
   его явно назначенными кампаниями. Для Kolvika эта связь обязательна. Кампании
   с несколькими счётчиками включаются только при явном назначении; GoalID
   проверяется для счётчика направления.
3. В `telegram_weekly_status_goals` добавить GoalID, бизнес-ярлык, вид цели и,
   при необходимости, подпись ценности. Для AI-лендингов отметить три обращения
   `include_in_contact_cpa = true`.

Цели одинакового смысла из разных счётчиков остаются разными строками. Результаты
агрегируются только внутри ключа `project_id + direction_id + counter_id + goal_id + date`.

## Данные и защита от ложных цифр

- Для направлений с `require_vat = true` расход попадает в статус только из строк
  `spend_includes_vat = true`. Для VK и Telegram Ads можно явно отключить это
  требование, указав правдивую подпись расхода в `spend_label`.
- Цель с отсутствующим или неполным измерением выводится как `нет данных`, а причина
  сохраняется в `telegram_weekly_status_deliveries.last_error` и журнале cron.
  Черновик владельцу приходит с предупреждением. Автоматическая отправка сотруднику
  при такой ошибке блокируется (`status = blocked`). Для привязанного кабинета проверяются
  успешная загрузка после конца отчётной недели и покрытие каждой строки
  кампании/дня по каждой выбранной цели.
- Если в выгрузке есть клики при нулевом расходе, расход и CPA помечаются как
  `нет данных`, а черновик содержит предупреждение для проверки типа оплаты.
- CPA не считается при нуле конверсий: цель получает `0 / —`.
- Ценность цели выводится только из её собственного `Revenue_<goal_id>_LC`. Для
  покупки без покупок показывается `0 ₽`; отсутствующая ценность — `—`.
- `display_title`, `show_direction_heading` и `spend_label` в сценарии позволяют
  настроить короткий статус одного направления без клиентских условий в коде.
- Резервный лист можно описать в `fallback_source` сценария и `fallback_match`
  направления, но он не заменяет нормализацию и не может смешивать разные счётчики.

## Kolvika

Сценарий Kolvika настроен для отправки только в личный чат владельца, сохранённый ботом
как `telegram_bot_settings.owner_chat_id`, по понедельникам в 08:00 МСК.
В чат Софы бот этот статус не отправляет: владелец пересылает проверенный пост
самостоятельно. Идемпотентный скрипт `scripts/configure-kolvika-weekly-status.sql`
создаёт сценарий **неактивным**, проверяет явные назначения кампаний и берёт
точный ID уже привязанного личного чата. Миграции 0046–0047 и сценарий внесены
в рабочую базу 26.10.2026. Сценарий пока неактивен: у Kolvika Center нет
нормализованных метрик за 19–25.10, а ценность корзин за эту неделю импортирована
неполно. Перед активацией нужно обновить данные и сверить полный пост. Направления:
`14496817` (Gems4U), `71291494` (Kolvika Center), `112938684` (AI-лендинги).

| Направление | Цели в конфигурации |
| --- | --- |
| Gems4U | Корзина `194376727`, Покупка `3014496817`, Клик по номеру `347388444`, Мессенджеры `157962814` |
| Kolvika Center | Корзина `224072509`, Клик по номеру `158184796` |
| Kolvika Jewelry — AI-лендинги | Отправка формы `661982976`, Клик по номеру `661983554`, Мессенджеры `661983342` |

Для корзины нужно задать `value_label = "Стоимость товаров в корзинах"`, для покупки —
`"Выручка по покупкам"`. У целей AI-лендингов нужно поставить
`include_in_contact_cpa = true`. Покупка и мессенджеры Kolvika Center не
добавляются до появления подтверждённых GoalID. Новые цели, направления и
получатели меняются в конфигурационных таблицах, а не в шаблоне бота.

## ИНОМ

Отдельный сценарий для проекта `Ином // СНТ`, кабинета `fortilda26` и счётчика
`109204270`. Для него нужен один блок без повторного заголовка направления:
`display_title = 'Отчёт ИНОМ (запасной аккаунт fortilda26)'`,
`show_direction_heading = false`, `spend_label = 'Расход'`. Две **разные** цели:

| Строка статуса | GoalID | Вид |
| --- | --- | --- |
| Страница «Спасибо» | `559741388` | form |
| CRM: Заказ создан | `559241229` | form |

Обе цели считаются отдельно: количество и CPA = расход с НДС / количество
достижений соответствующей цели. Не складывать их в «Заявки»: за 28.09–04.10
Agency OS показывает 9 достижений страницы «Спасибо» и 1 CRM-заказ, тогда как
в ручном примере было указано 10 заявок. Кампании без номера счётчика включены
явным списком внутри кабинета `fortilda26`. Данные кабинета обновлены 26.10.2026.
За 19–25 октября в Agency OS есть 346 кликов и 2 достижения страницы «Спасибо»,
но расход равен нулю. Поэтому бот должен помечать расход и CPA как `нет данных`;
точность источника нужно проверить до активации сценария. Статус предназначен
личному чату владельца по понедельникам в 08:00 МСК, без автоматической отправки Софе.
Подготовленный конфигурационный скрипт — `scripts/configure-inom-weekly-status.sql`;
он идемпотентен и при первом запуске создаёт **неактивный** сценарий.
